  <name>Task 1: Build Real Road Geometry Service with OSRM and Caching</name>
  <files>frontend/src/services/routeGeometryService.js</files>
  <action>
    Create `frontend/src/services/routeGeometryService.js`:
    - Define known landmark coordinate constants matching `backend/utils/geoHelper.js`.
    - `resolveCoords(name)`: Match user-entered pickup/destinations to known WGS-84 `[lng, lat]`.
    - `fetchRoadRoute(coordinates)`:
      - Accepts an array of `[lng, lat]` coordinates (`[origin, ...waypoints, destination]`).
      - Validates all coordinates.
      - Generates cache key from rounded coordinates (`toFixed(4)`).
      - If cached, returns immediately without network hit.
      - Queries public OSRM driving API (`https://router.project-osrm.org/route/v1/driving/...`).
      - Sets a 4000ms AbortController timeout.
      - On success: extracts `coordinates` (LineString), `distance` (meters -> km), and `duration` (seconds -> mins).
      - On timeout/error: falls back cleanly to dense Catmull-Rom or linear interpolation between waypoints, flagging `{ isFallback: true }`.
    - `getPointAndBearingAtProgress(coordinates, progress)`:
      - Given progress `t ∈ [0, 1]`, calculates exact position `[lng, lat]`, active segment index, and heading bearing angle in degrees `[0, 360)`.
    - `calculateCumulativeDistances(coordinates)`:
      - Computes cumulative Haversine distances for constant-speed vehicle travel regardless of vertex density.
  </action>
  <verify>
    Run a Node test script importing `routeGeometryService.js` to verify OSRM fetching, coordinate density, distance calculation, and heading angle computation.
  </verify>
</task>
